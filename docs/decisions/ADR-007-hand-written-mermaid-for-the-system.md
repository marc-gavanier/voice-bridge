# ADR-007 — Hand-written Mermaid for the system

**Date**: 2026-11-10
**Status**: accepted, partly supersedes [ADR-006](ADR-006-generated-diagrams-never-committed.md)

## Context

ADR-006 draws the code from its imports and leaves the path of a voice turn to words. The README then showed the system as a single line of text, and its readers could not see on GitHub which pieces run where, what speaks to what over which protocol, or how an interruption unfolds.

None of this is in the imports: the Mumble server, Claude Code, the Anthropic API and the Voxtral server are processes the bridge reaches at run time, and turn taking is behaviour over time. No tool can draw it from the code, so a diagram of the system is written by hand or not at all.

The [C4 model](https://c4model.com) is the standard for describing a system rather than its code. Its reference tool, [Structurizr](https://structurizr.com), keeps one model for every view, but GitHub does not render it: its pictures would have to be exported and committed, or published by the CI. GitHub renders [Mermaid](https://mermaid.js.org) in Markdown as it stands.

## Decision

- Describe the system in three Mermaid diagrams written by hand in the README, after the C4 levels: the context, the inside of the bridge, and a voice turn with its interruption as a sequence diagram.
- Use Mermaid flowcharts rather than its C4 syntax, which is still experimental and lays elements out poorly.
- Keep the code diagram generated by pydeps, as ADR-006 decided.

## Consequences

- The system can be read on GitHub without a clone or a build.
- Nothing checks the diagrams against the code: a change to a protocol, a process or turn taking must update them in the same pull request.
- The repository holds two kinds of diagrams: the system's, hand-written and visible, and the code's, generated and local.

## Alternatives considered

- **Structurizr DSL.** One model for every view and the reference implementation of C4, at the cost of an export to commit or a publication to maintain. Worth it once the system spans more than this repository, such as the whole homelab.
- **Words only**, as before. Nothing to maintain, but the topology and the interruption stay hard to picture.
